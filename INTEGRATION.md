# wirescope integration contract

**Hand this file to any tool that wants to integrate the wirescope into its product.**
It is the front door: what the proxy gives you, what to call, and what each call costs.
The push-feed event schema lives in its own deep-dive, [`SUBSCRIBERS.md`](./SUBSCRIBERS.md); this file is the index over the whole surface.

## The deal

wirescope sits transparently on the wire between an agent CLI (claude / codex) and the model backend.
It observes what only the wire can see; by default it **also applies a few deterministic, cache-coherent transforms** to the request (alphabetize `tools[]`, relocate the volatile `# Environment` block to the tail, an operator `omit` floor) plus any `[wirescope:…]` directives you opt into.
Every transform is deterministic and flag-gated; run it with `WIRESCOPE_PASSTHROUGH=1` for a byte-for-byte forward (`capabilities.passthrough` tells you which mode a given deployment is in).
Either way, observation never alters or blocks the byte path.
In return for routing through it you get:

- **the real per-turn bill** — priced usage from the response receipts (the CLI's own `total_cost_usd` under-reports);
- **prompt-cache warmth** — read/write split, whether the session prefix is warm and for how long;
- **refusals** — `stop_reason:"refusal"` is wire-only (the CLI shows a generic toast and the transcript shows nothing);
- **assistant text as it streams** — before the CLI renders it or writes the transcript;
- **the ability to keep a session's cache warm** between turns.

Cost to you: nothing on the byte path (capture is off-thread; a dead subscriber never blocks or fails an agent's stream).
The endpoints are **localhost, lab-grade, unauthenticated by default** — see Caveats.
A deployment MAY opt in to a control-plane token (`ENDPOINT_TOKEN` env): when armed, every `/_` endpoint **except `/_identity`** returns 401 without it — send `Authorization: Bearer <token>` (or `?token=<token>`).
Detect via `capabilities.endpoint_token` on `/_identity` (which stays open precisely so you can discover this before your first gated call).

## Step 1 — confirm it's us (`GET /_identity`)

Anything can sit on `ANTHROPIC_BASE_URL`.
Before you integrate, probe the proxy ROOT and check the product marker:

    GET http://127.0.0.1:7800/_identity        # read-only, unauthenticated, free

    { "product": "wirescope", "version": "...",
      "protocols": { "identity": 2, "subscribers": 1, "wirescope": 1 },
      "capabilities": { "passthrough": false, "subscribers": true,
                        "warmth": true, "ping": true,
                        "hold": true, "stats": true, "session_view": true,
                        "codex": true, "codex_websocket": true,
                        "wirescope": { "agent_name": true, "omit": true,
                                       "replace": true, "keep": true,
                                       "spawn": true, "strip_tools": true,
                                       "omit_default": ["useremail"],
                                       "spawner_hint": false } },
      "endpoints": { ... }, "docs": "INTEGRATION.md" }

`capabilities.passthrough` is `true` when the deployment runs with `WIRESCOPE_PASSTHROUGH=1` (verbatim forward, all transforms off); `false` means the default transforms + directives are active.

- **Branch on `product == "wirescope"`.** A different proxy 404s `/_identity` or returns a body without these fields — don't attempt wirescope-specific calls.
- **`capabilities.endpoint_token`** (bool): this deployment requires the control-plane token on every other `/_` endpoint (see the note above Step 1).
- **`capabilities.mutation_armed`** (`{inject, resp_mutate, shortcircuit}`): honesty panel — whether the proxy's first-party content-mutation experiment flags (request injection / response mutation / short-circuit) are LIVE on this deployment. All default off; a `true` here means forwarded conversations on this port may be altered by design. `passthrough:true` keeps them inert regardless.
- `capabilities` are the **live** flags of *this* process (env can disable a subsystem). Gate every feature on them — e.g. only call `/_ping` when `ping` is true. `endpoints` tells you where each one lives.
- Also returned as the `X-Wirescope-Version` response header (cheap sniff).

> **Deployed-state note (pre-`/_identity` builds, ≤ v0.2.7).** `/_identity` and the `capabilities` map post-date v0.2.7 — on those builds `/_identity` 404s and there is no `capabilities` object. Detect the proxy instead via `GET /_status` (200 with a `proxy.version` string), and read live subsystem state from `proxy.flags` (`hold`/`pinger`/`ledger`/`block_cold_ping`) and `proxy.subscribers.enabled`. Note also that on these builds `/_status.sessions` is a **list**, not a dict. Switch to the `product=="wirescope"` / `capabilities.*` handshake once the proxy reports a version that serves `/_identity`.

## Step 2 — route your sessions with an agent name

Everything session-scoped (subscriptions, stats, warming) keys off an **agent name**, which comes from the route.
Launch each session through:

    ANTHROPIC_BASE_URL=http://127.0.0.1:7800/agent/<name>/anthropic   # claude
    # codex: model-provider base_url http://127.0.0.1:7800/agent/<name>/openai

Codex traffic supports both the HTTP/SSE `/responses` path and Codex's
WebSocket-first `/responses` transport when `capabilities.codex_websocket` is
true. The WebSocket path is a raw tunnel with lightweight frame capture and
receipt finalization on `response.completed`; set `CODEX_WEBSOCKET=0` only as
an emergency fallback for older Codex clients that still retry HTTP/SSE.

Pick a prefix per app (`wb-alice`, `clodex-bob`).
Plain traffic with no `/agent/` prefix is observed but **never** pushed to subscribers and is not your addressable namespace.
(The `/_*` control endpoints above are always at the proxy root, NOT under your route prefix.)

## The three ways to integrate

| Mode | Endpoint | Method | Cost | What you get |
|---|---|---|---|---|
| **Discover** | `/_identity` | GET | free | Is this our proxy + live capabilities (Step 1). |
| **Pull** | `/_status[?session=<id>][&all=1]` | GET | free | Durable JSON: sessions, titles/agent, model, cwd, per-session + global cost, turn counts, context size (`context.input_tokens` = the wire-measured input-side token count of the last turn — cache_read + cache_write + uncached input, the same figure `/_session` shows; plus `turns_in_context` / `n_messages`), warmth, hold, refusal events, and **`busts`** — the per-session **real-bust** rollup (a *real* bust = a turn that LOST cached prefix — its `cache_read` came back shorter than the prior turn's, i.e. previously-cached tokens were invalidated + re-paid at the write premium — NOT the normal tail-append write every turn pays to cache its own fresh content. Since v0.6.49 this is measured as that shrink rather than inferred from the write fraction; see `/_bust` below for why the old rule was wrong in both directions). `null` when the session never had one. Shape: `{total, actionable (= total − lapse − compact, the busts a code/config change could have prevented), by_class:{tools, system, preamble, conversation, compact, lapse}, classes:[{class, count, fault, fix_hint} biggest-first], last_bust:{class, ts, write_tokens, fault, fix_hint}}`. The six **classes** are structural (divergences land at cache boundaries, not random offsets): `tools` (total bust — tools is first in cache order), `system` (near-total — model/prompt swap; covers the whole `system[]` array, so a change in a block past the last cache marker still files here, never as a false `conversation`), `preamble` (`messages[0]` = claudeMd/userEmail/currentDate/scratchpad changed → history re-writes, tools+system survive), `conversation` (a settled mid-history turn edited **in place** while the message count held/grew — usually one of OUR L2 transforms flapping), `compact` (the history **contracted** to a summary — a `/compact` or auto-compact, an expected one-time rewrite, distinguished from a flap by the sharp message-count drop), `lapse` (cache timed out, byte-identical bytes re-written). **Presentation semantics ride in the payload** so you render chip colour/severity from data, not a hardcoded class map — each class carries **`fault`** ∈ `self` (our transform bug — render loud) \| `content` (an injected-context byte changed — fixable by a peel/strip) \| `environment` (not our code + no per-turn fix: cache `lapse` → keep-warm, or a `compact` → nothing to fix) plus a human **`fix_hint`**. So a chip needing "should I worry?" keys off `actionable` (or `fault != environment`), not raw `total` — a session whose only busts are compacts/lapses is behaving normally. The `/_bust?session=` endpoint is the byte-level drill-down; `/_session?...&turn=` deep-links a specific bust. **Supersedes the old `cold_resumes` scalar** (which counted only the `lapse` class and missed every warm content-divergence bust — e.g. a midnight `currentDate` rollover); `lapse` now lives in `busts.by_class.lapse`. **Per-line cost decomposition:** `cost.est_usd` is the WHOLE session tree — subagents share the parent's `session_id`, so every line under it (main, each subagent, title side-calls) rolls into the one number. The split rides alongside: `cost.main_est_usd` = the main line's own share, and each `sub_agents[]` entry carries `est_usd` = that instance's share (same instance key as the `sub`/`child` params). **`sub_agents[].display_name`** (since v0.6.24) is populated wire-side for NAMED spawns too: precedence = `[wirescope:agent-name …]` directive → the pre-`@` name part of the agent-id header (skipped when it's an anonymous spawn's UUID/hex blob) → `null`; label chain for a consumer is simply `display_name → role`. `null` (never 0) for an instance with no billed traffic yet or for sessions recorded before this shipped; the offline twin for ended/historical sessions is `/_report` → `scope.agents[].est_usd`. **`since_compact`** (gate on `capabilities.since_compact`) = per-session `{turns, requests, est_usd, boundary_ts, compacted}` — the cumulative counters since the last compact boundary (detected wire-side as a decrease in `turns_in_context`; `compacted:false` means the baseline is the session's true start, no compact yet; `null` pre-feature/no-traffic). Persists in `_session.json`, so a proxy restart does not re-stamp the baseline. **Survives proxy restarts** — this is your source of truth for reconciliation. |
| **Pull (human)** | `/_admin` | GET | free | HTML render of `/_status` (dark, auto-refresh). For eyeballs, not parsing. |
| **Pull (human)** | `/_session?session=<id>[&turn=<i>]` | GET | free | HTML view of the session's captured context + last receipts + cache breakpoints. For eyeballs. **`&turn=<i>`** = the turn NAVIGATOR: render the `i`-th main-line captured request (0-based chronological; `-1` = latest, out-of-range clamps) with prev/next arrows and a **"vs previous turn" cache panel** — the per-turn face of the bust locator (this turn's cache read/write, which prefix boundary held warm, and, on a bust, the first byte-change vs the prior turn with an old→new snippet). Disk-based, works on ended/historical sessions. |
| **Pull** | `/_warm?session=<id>` *(or `?h=<prefix-hash>`)* | GET | free | Just the warmth verdict for one session: `warm`/`found`, `remaining_s`, `ttl_s`. |
| **Pull** | `/_context?session=<id>` | GET | free | **What's loaded for a session, per agent line** (main + each subagent). Returns `agents:[]`, each `{line:"main"\|"subagent", role, agent_id, display_name, model, wire, tools, skills, composition}`. **`tools`** = `{count, names, total_schema_chars, est_tokens, per_tool:[{name, schema_chars, est_tokens}]}` (`per_tool` biggest-first — the "what to trim" view). **`skills`** = the same shape for the CLI's injected skills list (`per_skill` instead of `per_tool`, biggest-first), parsed from the skills block on either wire shape; `null` when no skills are loaded or for a codex body. The skills trim lever is `skillOverrides:{name:"off"}` (`permissions.deny Skill(name)` is invocation-only — tokens still ship). **`composition`** = the per-category token breakdown of the whole context window — *what is taking up context*: `{total_tokens, basis, by_category:[{category, tokens, pct}]}`, `by_category` biggest-first. Category vocabulary (render generically, map any future addition to "other"): `system, claudemd, useremail, agents, skills, tools, user, assistant, thinking, tool_calls, tool_results` (file reads & command output land in `tool_results`; `claudemd`/`useremail` are split out so a consumer can attach the matching `[wirescope:omit …]` trim lever; `agents` = the CLI's injected agent roster and `skills` = its skills list — ~hundreds of tok/turn that would otherwise hide inside `system`. The proxy detects both wire shapes (the older `<system-reminder>`-wrapped block in `messages[0]`, and the opus-4-8 `mid-conversation-system` form where the roster + skills arrive concatenated in a trailing `role:"system"` message). Trim levers differ: skills reclaim via `skillOverrides:{name:"off"}` in settings (`permissions.deny Skill(name)` is invocation-only — tokens still ship); the agent roster is effectively a fixed cost in the CLI/PTY path (built-ins always present on the wire), so treat `agents` as visibility, not an actionable trim. **`skillOverrides:{name:"off"}` is wire-confirmed to bank the tokens** (measured: skills composition 925→666 tok, roster 8→7 with the disabled skill gone — the `deadweight_tokens` you compute is exactly this reclaim). ⚠️ **It only takes effect on a FRESH conversation eval**: the skills roster is frozen at session *creation*, so `--resume`/restart replays the old roster and the override does NOT apply — a `/clear` (or a non-resume start) is required for a skills `skillOverrides` change to land. (This is skills-specific; `permissions.deny` for tools enforces per-invocation and works on resume.) `basis` = `"receipt"` on the main line (categories scaled to the real wire-measured `input_tokens`, so the breakdown sums to the same total `/_status` reports) or `"estimate"` on subagents (char-derived, no usage receipt). Rosters & composition are the **actually-forwarded** content (post-wirescope-trim). In-memory only: a cold/ended session returns `agents:[]` + a `note`. Codex/openai-wire entries report `wire:"openai"`, `tools:null`, `composition:null`. |
| **Pull** | `/_context?session=<id>&utilization=1` | GET | cheap (one disk scan) | **Did the loaded tools pay off?** Opt-in extension of `/_context` — adds tool *usage* to each agent line so you can spot deadweight (loaded every turn, never called). Off by default (a per-session capture-dir scan, so keep it off the fast poll; fetch on-demand, e.g. when a user opens a context popover). When on: each `tools.per_tool[]` entry gains **`used`** (raw invocation count over the session — 3 Reads in one turn = 3), `per_tool` is re-sorted **deadweight-first** (never-used first, then biggest schema = the trim list), and each agent gains **`utilization`** = `{basis:"capture-scan", evaluable_turns, loaded, used_distinct, deadweight_tokens}`. `deadweight_tokens` = the per-turn schema carriage of currently-loaded tools that were never called — the concrete "free up ~N tokens" payoff to attach the trim lever (`--tools` for the main agent, `[wirescope:strip-tools …]` for subagents). `evaluable_turns` = tool-loading turns that actually ran (200) — read `used:0` against it for confidence (`0/2` inconclusive, `0/40` dead). The same scan also prices **skills** the same way: each `skills.per_skill[]` gains `used` (skill invocations, counted from assistant `Skill` tool_use blocks by `input.skill`, deduped across the history that re-ships them), re-sorted deadweight-first, plus a per-agent **`skills_utilization`** rollup of the same shape — `deadweight_tokens` there is the `skillOverrides:{name:"off"}` reclaim payoff. Scoped to the live `session_id` (one capture dir → never spans a `/clear`). Gate on `capabilities.context_utilization` (skills usage rides the same flag); turns captured before this shipped lack per-subagent attribution (they fold into the main line). |
| **Pull** | `/_report?session=<id>[&detail=1]` | GET | cheap (one disk scan) | **Where did this session's tokens and dollars actually go — and is it optimal?** The on-demand, **disk-based** cost/efficiency report (works on **ended/historical** sessions, unlike the in-memory `/_context`). Heavy (scans the whole capture dir) → on-demand only, e.g. behind a "Full report →" link, not the poll loop. Returns a **versioned** payload (`report_version`, the coupling surface) — the quantitative truth (pricing, cache math, thresholds, verdict) stays here so every surface agrees; you render prose. Top-level: `scope` (`turns` = genuine user prompts — the human "turn"; `requests` = wire requests, **the carriage multiplier** — one user turn fans out into many tool-loop requests, each re-sending the prefix) · `totals` (summed per-request billing — **NOT** the global `cumulative`) · **`cost_decomposition`** = where the *dollars* went in real cache rates: `by_bucket:[{bucket, usd, pct, tokens}]` over `cache_read` (the preamble tax — typically the bulk), `cache_write_initial`, `cache_write_rewrite`, `uncached_input`, `output`, plus **`cache_misses`** = `{count, usd, tokens, where, by_cause, events:[{where:"preamble"\|"conversation", suspected_cause:"idle_gap_gt_ttl"\|"eviction", idle_gap_s, usd, tokens}]}` (a *localised drill-down* of the `cache_write_rewrite` bucket — already counted there, NOT an extra addend) · **`token_decomposition`** = where the *tokens* go (char-estimate), with `preamble:{tokens_per_request, requests_resent, total_resent_tokens, used_tokens_per_request, unused_tokens_per_request, by_category}` · **`findings`** = flat, sorted by `reclaimable_usd` desc, each `{id, category, line, title, detail, reclaimable_tokens(_per_turn), reclaimable_usd, turns, evidence, confidence:"high"\|"medium"\|"low", additive, lever}` (price honestly: deadweight rides cache as a 0.10× read every turn + one write, not full input rate; the `cache_misses` finding's `reclaimable_usd` is **net/marginal** — gross write minus the 0.10× read you'd pay even kept warm, with `evidence.gross_write_usd`/`read_equiv_usd` shown) · **`waste`** = the consolidated *"what could have gone better"* — the **avoidable subset** of cost priced as the real *net* saving, aggregated by type across all agent lines: `{total_usd, pct_of_session, by_type:[{type, usd, tokens, items, confidence, lever}], basis}`. Types: `cold_cache` (marginal), `deadweight_tools`, `deadweight_skills`, `claudemd_carriage`, `useremail_carriage`. **`waste.total_usd == verdict.reclaimable_usd_total`**. Distinct from `cost_decomposition` (which is *gross* — every dollar actually paid); `waste` is what better choices reclaim. **(v4) `claudemd_carriage`/`useremail_carriage` are SUBAGENT-scoped** — the `[wirescope:omit …]` lever only shapes subagent spawns, so only a subagent's *inherited* claudemd/useremail counts as reclaimable. Main-line claudemd/useremail is intentional in-use context with no main-line lever → surfaced as an **informational, non-additive** finding (`category: main_claudemd_carriage`/`main_useremail_carriage`, `reclaimable_usd: 0`, excluded from `waste` and the score; `evidence.carriage_usd_if_omittable` shows the hypothetical). Render these dimmed like other non-additive findings. · **`verdict`** = `{rating:"optimal"\|"suboptimal"\|"wasteful", score:0-100 (higher=better; driven by high+medium *additive* reclaimable only — low-conf never moves it), headline (plain factual sentence default), reclaimable_usd_total, reclaimable_pct, confidence}` · **`invariants`** (assertable: `Σ by_bucket.usd == totals.est_usd`; `preamble.unused_tokens_per_turn == Σ deadweight findings`; `cache_misses.usd == cache_write_rewrite bucket`). Group reclaimable by each finding's `lever` (trim-config / keep-warm / omit) for the render. Low-conf findings (`redundant_tool_calls`, `cheaper_tool_available`) are `additive:false`, score-excluded → render dimmed. **`detail=1`** adds **`series`** = the per-request cost timeline (main line, chronological): `{count, spine_buckets:["read","write","generation"], spine_totals:{read, write, generation, read_cached, read_uncached}, content_carriage_est:{preamble, conversation, thinking}, requests:[{i, ts, read_usd, read_cached_usd, read_uncached_usd, write_usd, generation_usd, total_usd, window_tokens, bands:{preamble, conversation, thinking}}]}`. The **spine is three receipt-exact $ buckets** — `read` (the model consuming the window: cached at 0.1× or uncached at 1× — same activity, two prices, folded into one `read`), `write` (the toll to cache so later reads are ~10× cheaper), `generation` (output tokens). Invariants: `read == read_cached + read_uncached`; per-row `total_usd == read+write+generation`; `Σ spine == totals.est_usd` for a main-line-only session; **`Σ content_carriage_est == spine.read`** (the content split apportions the READ $ — not read+write — so a "what the read pays to re-carry" pie ties exactly to the read bucket). `content_carriage_est` is an ESTIMATE (read $ apportioned by char-token share — same basis as `/_context` composition). Cold/unknown → `scope.requests:0` + `note`. Gate on `capabilities.context_report` (`context_timeline` for the series). |
| **Pull** | `/_timeline?session=<id>` | GET | cheap (one disk scan) | **HTML cost-evolution dashboard** — the human-facing companion to `/_report?detail=1` (renders the same `series`). Pie of the three exact buckets (read/write/generation) + an estimate drill-down pie (what the read pays to re-carry: preamble/conversation/thinking) + a cumulative-cost-by-bucket line chart (turn 0 → last, where `read` visibly bends super-linearly while write/generation stay flat). Self-contained dark HTML, zero JS; disk-based, works on ended/historical sessions, main line only. Link as a "Cost over time →" button; gate on `capabilities.context_timeline`. |
| **Pull** | `/_bust?session=<id>` | GET | cheap (one disk scan) | **Where did the cache bust?** Disk-based cache-divergence forensics over the session's main line, chronological. Walks adjacent request pairs and, per transition, decides from the RECEIPT whether cached prefix was **lost** and how much (`severity: append`\|`partial`\|`full-rewrite`, `lost_tokens`, `lost_frac`, `quasi_full_rewrite`), then localizes it two ways: **`survived_prefix`** = the deepest cache boundary the receipt's `cache_read` covered (`{boundary:"tools"\|"system"\|"messages[i]"\|"none", est_tokens}` — the bill's own answer to how deep the cache held) and **`locus`** = the first byte-change vs the previous forwarded turn (`{segment:"tools"\|"system"\|"messages", index, label, char_offset, old, new}` — the human-readable *what* changed: a model-flavor swap, a `# currentDate` rollover, a transform toggle). **What counts as a bust (changed in v0.6.49 — re-read this if you cached the old semantics):** a bust is a **LOSS of cached prefix**, measured as this turn's `cache_read` coming back shorter than the previous turn's (floored at one cacheable block, 1024 tok). It is NOT "a big write" — the earlier rule flagged any turn whose write was >=15% of its priced window, which fired on sessions that merely GREW (a large write on a small early window; 1,100 false alarms in a 61.8k-transition corpus sweep, and the report that prompted the fix was a clean session flagged 4 times) and stayed silent on real lapses that re-read a short static floor while writing little (2,046 missed, worst 138k tokens lost at `write_frac` 0.00). `write_frac` is still reported — it is the honest "share of this window newly written" — but it is no longer the test, so **do not re-derive bust-ness from it**. `lost_tokens` is the magnitude to display and to rank by; `unread_write` (on non-bust turns) is the CLI's normal deferred tail, written past the last breakpoint and swept into the cache a turn later — visible, but not damage. **`static_prefix_bust:true`** flags the actionable class — the cached preamble (tools / system / `messages[0]` claudeMd bundle) changed, distinct from a routine cold-resume history rewrite. Payload: `{count, n_busts, n_static_prefix_busts, worst, static_prefix_busts:[…], busts:[…]}`. **`?detail=1` adds `transitions:[…]`** — one entry per turn, whether it busted or not (same opt-in convention as `/_report?detail=1`'s `series`). Since v0.6.48 that array is OFF by default: it was ~96% of the payload (5.1 MB of 5.3 MB on a 7,132-turn session) and the counts/loci a chip or popover needs all live in `busts`/`count`/`n_static_prefix_busts`. Ask for `detail=1` only if you plot per-turn history; the summary answers "how many, how bad, where" on its own. Cost is *one receipt-first disk scan*: bust decisions come from the billing receipts + two small header reads per turn, and request BODIES are parsed only for turns that actually busted (~100 of 7,132), so a long session answers in ~1.5s rather than ~16s. Gate on `capabilities.bust_locator`. The `/_session?...&turn=` panel is the per-turn HTML face of this. |
| **Pull / Act** | `/_prune` | GET / POST | GET free · POST destructive | **Capture-dir retention** (gate on `capabilities.prune`). The corpus only grows (~800 KB/Opus turn of request bodies); the heavy files and the valuable files are mostly *different* files, so retention is **two-tier**, not delete-or-keep. **GET** = free size readout, no deletion: `{total_bytes, sessions:{count, bytes, body_bytes, receipt_bytes}, no_session:{files, bytes}, other_bytes, reclaimable:{bodies, full, no_session}}` — `reclaimable.*` = what a prune at the operator's default cutoffs would free (`{older_than_days, sessions|files, bytes}`); source your size display + confirm-dialog numbers from here (one poll, no fs walk of your own, survives format changes). **POST** `?older_than=30d[&tier=receipts\|full][&scope=sessions\|no-session\|all][&dry_run=1]` — `older_than` REQUIRED (`30d`/`12h`/seconds, floor 1h; 400 if missing/malformed — the only 4xx), default `tier=receipts` `scope=all`. `tier=receipts` deletes body files (request bodies + SSE ≈ 95%+ of bytes) from session dirs idle past the cutoff but KEEPS the billing receipts — `/_report` still prices those sessions fully (incl. the per-line split); only byte-level forensics (`/_bust` diffs, `/_session` bodies) die. `tier=full` removes the whole dir (cost accounting too) — for much older sessions. `scope=no-session` ages out the probe/count_tokens bucket (no forensic value; always full-delete of old files). Age = the dir's NEWEST file mtime, so any activity resets the clock; sessions that are warm in the ledger or hold-armed are never touched regardless of age (`skipped:{recent, warm, held}` reports why). Response: `{ok, dry_run, tier, scope, sessions_scanned, sessions_pruned, files_deleted, bytes_reclaimed, skipped}` — flow: `dry_run=1` preview → confirm with the numbers → POST for real. On-demand only: nothing runs unless called (no background sweep). Idempotent per tier (a receipts-pruned dir is a no-op on the next receipts pass). |
| **Act** | `/_ping?session=<id>[&force=1]` | GET/POST | **~1 token** | One-shot: replay the session's cached last request to slide the cache TTL once. Declines by default if the prefix is provably cold (`force=1` re-warms anyway). Spends credits. |
| **Act** | `/_hold?session=<id>&hours=<n>[&force=1]` | POST | free to arm | Arm **N hours of idle insurance**: the proxy auto-pings to keep the prefix warm until N hours after the session's last real turn (re-anchored on every turn). **Declines a cold/absent prefix** (`armed:false, skipped:<state>`) — arming over HTTP doesn't forward a turn, so there'd be nothing to keep warm (`force=1` arms anyway, e.g. when a turn is imminent). `hours=0` or `&action=off` disarms (never gated); `GET /_hold?session=<id>` reads current state. Arming is free; the auto-pings it schedules each cost ~1 token. The programmatic twin of the in-band `/warm-cache` command. |
| **Act** | `/_end?session=<id>[&reason=...]` | GET/POST | free | Mark a session finished (wire to your SessionEnd): disarms any hold, stops caching it, emits `session.ended` to subscribers. |
| **Pull** | `/_subagents?session=<id>&child=<key>[&detail=1][&maxlen=N]` | GET | free | On-demand per-subagent detail (a child-row popover): `child` = a `sub_agents[].key` from `/_status` (the same key serves row and detail). Returns `{found:true, role, model, display_name, turn_ts, last_text, last_tool, last_tool_input, truncated}` from that instance's latest forwarded request body — **one turn stale** by design (never the in-flight stream; `turn_ts` gives an honest "as of Ns ago"). `maxlen` clamps string values in place (JSON structure preserved; `truncated:true` iff any clamp fired) so a popover never pulls full file bodies. Absent cases at 200: `{found:false, reason:"unknown_child"\|"no_request_body"\|"session_cold"}`; 400 only on missing params. In-memory — keep it off the poll path, fetch on popover open. |
| **Act** | `/_compact?session=<id>&path=<jsonl>[&level=N]` | POST | free (disk rewrite) | **Offline transcript bake** for a PARKED session (the compact-on-resume flow): rewrites the session's JSONL on disk to the maximal safe-to-drop set — v1 bakes **thinking only** regardless of `level` (whole-block deletes, signatures untouched; L2 folds stay wire-only → `folds_deferred:true`, `baked_families` is authoritative). Pass the explicit transcript `path` (the proxy never guesses; since 2026-07-19 it must resolve under `~/.claude/projects` or a `COMPACT_PATH_ROOTS` override → else `{ok:false, reason:"path_outside_root"}`). Integrity-gated, `.bak-<ts>` backed up, atomic, idempotent (`noop:true` when already slim); preserves session_id so `--resume` still resolves. On any problem returns `{ok:false, reason:not_found\|unreadable\|not_a_transcript\|session_mismatch\|chain_integrity\|path_outside_root}` at 200 — key control flow on `ok` and resume the ORIGINAL untouched. Success carries `lines_in/out`, `thinking_lines_deleted`, `tokens_removed` (est), `backup`, `warmth_state`, and `wire_delta.classification` (`already_live` = the wire was stripping it anyway, disk-only win; `wire_carried` = durable token win + one-time re-cache on next forward). |
| **Act / Pull** | `/_strip?session=<id>&on=1\|0` *(or `&level=0\|1\|2`, `&action=clear`)* | GET/POST | free | Per-session override of the prior-thinking strip ladder — the programmatic twin of the `[wirescope:strip-thinking …]` body directive (see WIRESCOPE.md). `level=1` = thinking-only, `level=2` = + the settled-history riders, `on/off` = legacy 1/0 alias, `action=clear` drops back to the deployment default; GET reads effective state. A bare POST with none of these is a 400 (it no longer implies on=1). The actual strip is cold-gated + latched per session (opting in mid-session never busts a warm cache). |
| **Act / Pull** | `/_hint?agent=<route-name>&on=1\|0` *(or `&action=clear`)* | GET/POST | free | Per-agent toggle of the spawner grammar hint — the A/B **invisibility gate**: `on=0` makes wirescope fully invisible to that agent's model (the hint is the lone model-visible proxy-authored text) while capture/billing/warmth still run. Keyed by the agent ROUTE name (works pre-launch, survives `/clear` id-rotation), persisted owner-scoped across restarts. Set BEFORE the arm's first turn — flipping mid-session busts the marked system prefix. |
| **Act / Pull** | `/_hints[?agent=<pattern>][&session=<id>][&native=<names>][&id=<hint-id>]` | GET/POST/DELETE | ~$0.0002/carrying request | **Tail hints** — short model-visible strings injected as an UNCACHED trailing block, never in the CLI transcript. **Full contract: [`hints_contract.md`](./hints_contract.md).** Two scopes by who owns the truth: `?agent=` = constant prohibitions, persisted, **use a glob** (`clodex-*`) since managed hops rewrite the route name; `?session=` = transient facts, in-memory only, **`ttl_s` REQUIRED**. `&native=` enables proxy-measured facts by name (the consumer never writes those bodies). Caps (800ch/hint, 2000ch total, 16/scope) **decline rather than truncate**. Per-hint **`turn_start_only`** rides only the first request of a turn — hint tokens are uncached at 1× on *every* request, so a hint answering "what the user just typed" is pure carriage by round 14 of a tool loop. Feature-detect on `/_identity` `capabilities.hints`. |
| **Act** | `/_deliver?session=<id>` | POST | — | **Throwaway prototype, do not build against it.** Mid-flight text injection into the session's next request; dead unless the deployment sets `DELIVER_PROTOTYPE=1` (`{ok:false, reason:"DELIVER_PROTOTYPE off"}` otherwise). No ack/receipt/dedup contract yet — the real design lands only if the experiment clears. Listed here so you don't mistake it for an undocumented stable surface. |
| **Push** | `/_subscribe` | GET/POST/DELETE | free | Register an HTTP endpoint + agent globs; receive `text.delta` / `turn.completed` / `session.ended`. **Full schema: [`SUBSCRIBERS.md`](./SUBSCRIBERS.md).** |

**Retired: `/_pot` (boiling-pot tier 2), removed 2026-08-11.** It returned per-file redundant-read heat, and it worked — the hypothesis behind it is what came back negative. Measured over a live 30-day window: 130 of 7,425 classified reads were redundant (1.75%), 94.8% of files had zero redundancy, and 61% of what remained was scratchpad `.diff`/`.patch` re-reads rather than source. Priced against the same window's real spend, that is ~0.03% of the bill — against tool-trimming at −72.7% and thinking-strip at 16–22%. Redundant reads are not where the money is, so the producer is gone rather than carried. A consumer that still calls it gets a 404; the tier-1 carriage ranking it fed was always additive and renders without these columns. The `file_heat` rows already collected are left in place (they simply stop growing) — retiring a feature is not a reason to drop data.

**Status-code convention.** HTTP status reflects whether the *request* was valid, not whether the side-effect happened. `2xx` = the proxy understood and processed it; read the body for the outcome (`ok`, and per-endpoint `armed` / `warmed`, with `skipped:<reason>` when the proxy deliberately did nothing — e.g. declining to warm a cold prefix). `4xx` is reserved for malformed/unfulfillable requests (missing `session`, bad `hours`). So **branch on the body's outcome fields, not on `2xx` alone** — a 200 can still mean "I chose not to act, here's why."

Rules of thumb:

- **Push for liveness, pull for truth.**
  The subscriber feed is at-most-once, fire-and-forget, no ordering, and suspends after repeated delivery failures.
  Whenever you reconnect or suspect a gap, reconcile from `GET /_status?session=` (durable).
  Don't treat the push as your ledger.
- **Keeping cache warm: three ways, pick by who's driving.**
  `POST /_hold?session=&hours=N` — arm once and let the proxy keep the prefix warm for N idle hours; the simplest programmatic option (you don't run the loop, the proxy does). Like `/_ping`, it **won't arm a cold/absent prefix** (replies `200` with `armed:false, skipped:<state>`): there's nothing to keep warm until a real turn establishes the cache — pass `force=1` to arm anyway. On success the reply's `pingable:true` confirms there's a replayable request + live auth to ping. Rely on those structured fields, not the human `ack` string.
  `GET/POST /_ping` — one-shot TTL slide if you'd rather own the cadence and cost yourself.
  `/warm-cache <hours>` — the bundled client's slash command; same hold as `/_hold`, but armed in-band by injecting a `<proxy:warm-cache hours=N>` sentinel into a forwarded turn (so it also donates auth + rewrites the cache). Use this when a human/agent is at the CLI; use `/_hold` from code.

## Shape the context on the wire — directives (`wirescope:`)

Beyond the HTTP endpoints, wirescope honors an in-band control channel: **`[wirescope:...]` directives** the proxy reads off a request, acts on, then **strips before forwarding** — so the model never sees them and they cost zero prefix tokens.
This is how you trim or rewrite the context the CLI auto-injects (project `CLAUDE.md`, the user's email) — things the wire otherwise gives no knob for.

There are two placements, and **an integrating app cares most about the second**:

- **Body directives** — written into an agent's `.claude/agents/*.md` body. A property of the agent *type*; the agent's author opts in.
- **Spawn directives** — written at the **strict head of the prompt you hand a spawn**. A property of the *call*: your app can shape any spawn's context **without editing the agent**, including uneditable built-ins (Plan / Explore / general-purpose). Just lead the spawned prompt with the directive(s). They **persist for the whole life of that subagent instance** — the proxy remembers them per instance (keyed by the `x-claude-code-agent-id` it sees on the wire) and re-applies them on every later turn, even after the spawn prompt scrolls out of `messages[0]` (a follow-up, a `/clear`, or a compaction summary). You set it once at spawn; you do not re-send it each turn.

The verbs:

| Directive | Effect |
|---|---|
| `[wirescope:agent-name <label>]` | Give the (otherwise nameless) subagent a display label in `/_status` + `/_admin`. |
| `[wirescope:omit claudemd,useremail]` | Drop the `# claudeMd` / `# userEmail` sections from the first user message — reclaims tokens (claudeMd is usually the bulk) and reduces fable refusal-classifier hits. |
| `[wirescope:replace claudemd <inline text>]` | Keep the section heading but swap its body for a one-line substitute (e.g. point the agent at a leaner doc). Single-line; for more, `omit` and write your own. |
| `[wirescope:keep <targets>]` | Override verb — cancel an `omit`/`replace` a body default would apply (precedence: spawn > body). |
| `[wirescope:tools Read,Glob]` | Allowlist a subagent's tool roster — the biggest per-turn lever (the ~33-tool / ~24k-token default that native `--tools` can't reach for a subagent). `strip-tools <names>` is the denylist variant, `keep-tools <names>` the override. Gated by `WS_STRIP_TOOLS`. |

Example — spawn a stock `general-purpose` subagent but strip the project CLAUDE.md and email from *this* call:

    [wirescope:omit claudemd,useremail]
    Search the repo for all callers of foo() and summarize.

**Feature-detect before relying on it:** `capabilities.wirescope` (from `/_identity`) reports `{agent_name, omit, replace, keep, spawn, strip_tools}` as live booleans (a deployment can disable `omit`/`replace` via `WS_OMIT=0`, the tool-roster verbs via `WS_STRIP_TOOLS=0`, or spawn-position reading via `WS_SPAWN_DIRECTIVES=0`). It also carries two operator-configured fields:

- `omit_default` — the list **already stripped from every subagent spawn** with no directive at all (e.g. `["useremail"]`). Check it before adding your own `omit`; the universal case may already be handled.
- `spawner_hint` (bool) — when on, the proxy appends one self-contained line to spawn-capable **main** agents pointing them at this directive grammar. It's a discovery aid the *agent* sees, not something you call; if your app already teaches its agents the grammar you can ignore it.

`protocols.wirescope` is the grammar version. `omit`/`replace`/`keep` only *do* something where the directive is present — no directive, no change.

**Full grammar, safety model, and the omit-target registry: [`WIRESCOPE.md`](./WIRESCOPE.md).**

## Caveats (read before you ship)

- **Localhost, unauthenticated, lab-grade.**
  No ACL today: any local app can register any agent glob and `/_ping` (which spends credits).
  Fine for a single user's machine; do not expose the proxy beyond loopback without adding a token gate.
  `/_subscribe` honours `SUBSCRIBERS_TOKEN` and loopback-only callbacks if the operator sets them; the rest are open.
- **Capabilities are runtime.**
  Re-read `/_identity` rather than assuming a subsystem is on — a given deployment may run with `SUBSCRIBERS=0`, `WARMTH_PINGER` off, etc.
- **Agent-routed traffic only.**
  Subscriptions and most per-session value require the `/agent/<name>/` route.
  `ext` (un-routed) traffic is observed for the operator's own `/_status` but is not yours to subscribe to.
- **Additive versioning.**
  New fields/events won't bump a protocol number; breaking changes will (`protocols.identity`, the subscriber envelope `v`).
  Ignore unknown fields.
